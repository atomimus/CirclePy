## Published source and compatibility

Downloaded the 0.5.1 sdist via the [PyPI release metadata](https://pypi.org/pypi/circlepy/0.5.1/json),
verified its advertised SHA-256
`ac8aa0d6c97901bbbe38eb8d849ce7527ca42d4564a57f1ecfdba65e0b82f2c8`,
and parsed its source without extracting/executing it. The
[signature snapshot](../published-0.5.1.json) captures all 146 public class
method/constructor symbols and the three package exports. The offline check
confirms original callable positional names/order/defaults and imports remain compatible;
the uncallable AsyncCircleClient constructor is explicitly exempted from preserving
its wildcard arguments when it gains a concrete implementation.
new reaction/filter parameters are appended optional arguments. Behavior is
checked separately by the regression suite. The published README Headless proxy
constructor example also passes with authentication mocked, both from source
and in clean artifact installations. No real member authentication was performed.

The contract retains the eager sync Headless constructor, legacy successful
return shapes, proxy dictionaries and error-dictionary defaults, and defines
network-free async constructors/awaited auth factories, token restoration,
session ownership, errors, cancellation, pagination and deprecation rules.
It intentionally raises the future minimum Python from advertised 3.7 to 3.11.
These planned features are not claimed as baseline implementations.

Known SDK defects are not mislabeled provider limitations: AsyncCircleClient
still raises NotImplementedError; SSO sends `sso_id` instead of documented
`sso_user_id` (Task 05); general transport timeouts/error handling/mutation replay
need Task 04; uploads/content preservation need Task 06. Provider limitations:
the Member schema omits basic-post update, API entitlement is account-dependent,
Data is an add-on, and live/financial test capabilities have not been established.
The dedicated sandbox task must resolve those access/evidence questions.
