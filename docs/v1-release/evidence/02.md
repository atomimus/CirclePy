## Changes and compatibility

`pyproject.toml` is the only metadata/version source. Name, author/contact and
repository identity are preserved. Metadata now accurately describes the existing
sync clients instead of promising implemented async support. CPython >=3.11 is
intentional v1 development policy; users on older runtimes keep the previously
published 0.5.1 artifacts. No new 0.5.1 or 1.0.0 package was uploaded.

Before deleting the duplicate `setup.py`/`setup.cfg`, copied the candidate source
to ignored `.venv/task02/candidate` without those files and successfully performed
a constrained editable install on 3.11, an isolated sdist build, and a wheel build
from that sdist. Removed the legacy files only after that proof. Setuptools adds
an `egg_info`-only `setup.cfg` inside its generated sdist; it contains no duplicate
project metadata and is explicitly checked by the archive validator.

`requirements.txt` delegates to the local project. The `dev` extra declares build,
twine, PyYAML and pip tools; `constraints-dev.txt` pins all 47 resolved development
and runtime requirements, using OS/Python markers. The build backend has its own
exact pin because pip constraints do not automatically govern an isolated build
environment. Consumer dependencies remain bounded ranges. No new HTTP transport
dependency was introduced.

Added the three existing package client names to `__all__` and minimal constructor
input/return annotations. The 146-symbol compatibility check still passes; no
positional name, order or default changed. The async stub and the pending SSO wire
correction remain explicitly assigned to later tasks. No `py.typed` is shipped:
partial annotations do not constitute a completely typed public package.

License provenance was verified in actual history: initial commit
`bc647f7302668258c6b599546eb30783cb863548` added MIT text with `Copyright (c) 2024
Atomimus`; commit `9d0f6a91105ca8709a5306cd61bf109adfbce77b` deleted it. Restored
those exact original bytes and attribution, without inventing ownership or dates.
The existing setup metadata consistently identified the MIT license.

The sdist includes source, the restored license, README/contributor setup,
constraints, synthetic tests, distribution verifier and sanitized release
documentation/specifications. The wheel contains the 35 Python source files,
README metadata and license (40 files total). `MANIFEST.in`, explicit package
discovery, disabled implicit package data and archive inspection exclude local
environments, caches, credentials and nested build outputs. Removed only the two
reviewed stale checked-in dist artifacts and now ignore generated `dist/` files.
Their removed SHA-256 hashes were `2d041274da35c99c07958fd1463a153f36134ad09bdb7a31e320f91528e245a6`
(old wheel) and `e6ba9ee8e10df7c294e781ce3d0f1c31a82bf9f56aafa3c0d54572699df145df`
(old sdist); neither supplied any validation evidence.
